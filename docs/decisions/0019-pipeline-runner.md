## Background

Phase 1 of the design is "the pipeline, triggered step by step". `pipeline/llm.py` (0015) runs one part of one prompt and says where each output belongs (00 §F2), but writing files and opening pull requests is left to its caller, and no caller existed. The first real use is APP's FY2026Q3 pre-registration (STATUS T11): the question list (14Q) is frozen, then the pre-registration (15A) is written and merged by 2026-10-30. The first monthly letter (18, T12) is due by 2026-11-02. STATUS T7 asks for a persistent call log that the budget guard reads.

Constraints that shaped the design:

- EDGAR is read with the SEC User-Agent that lives only in the workspace `.env` (0013, 0017); it must never reach GitHub.
- The inputs of most parts are private (the owner's report, private notes); public Actions logs are world-readable.
- 00 §G6: roles see only their `can_see` inputs; the blind read, the red team and the audits get stripped inputs.
- Pre-registration headers (`event`, `deadline`) are the pipeline's, not the model's (15A); the files are timestamped after the merge into main and are immutable after the deadline (0018).
- Owner decision (2026-09-25): model calls run by default through the Claude Code CLI on the owner's Max subscription, locally (`claude -p` with a system prompt, model, effort and JSON schema, no tools, no settings or MCP, in an empty temporary directory), with the Anthropic API as the fallback. The CLI backend will be added to `pipeline/llm.py` by a follow-up change.
- Owner policy (2026-09-25, 0020): the public repositories are English-first.

Questions the design documents do not answer: where inputs are assembled; how a call is tied to the exact inputs and code; where the call log lives; how outputs reach review and then the public repository; what a part gets when a declared input has no data yet; how everything is tested before any model access.

## Options

1. **Where inputs are assembled:** (a) inside the job that makes the model call; (b) locally, into a bundle committed to the private repository.
2. **What a bundle pins:** (a) nothing: whatever code and prompts are current when it runs; (b) input hashes, prompt hashes, the public commit whose pipeline code runs it, and the thesis-ci schemas the model was shown.
3. **Where the model call runs:** (a) only in the private repository's Actions; (b) locally by default, through a backend chosen per run (the Claude Code CLI, the API, a fake), with the private repository's Actions kept as an API route.
4. **The call log:** (a) llm.py's default `logs/` (not versioned); (b) one log per run only; (c) a persistent `runs/llm-log.jsonl` in the private repository, plus the run's own lines in its bundle.
5. **Declared inputs without data:** (a) omit them; (b) fail; (c) fail only when data should exist, give an explicit "nothing yet, because ..." document otherwise, and declare stand-ins.
6. **The pre-registration header:** (a) as the model writes it; (b) deterministic from `edgar.prereg_header()`.
7. **Public outputs:** (a) written straight to the public main; (b) written locally onto a branch of the public repository for a pull request.
8. **Testing before any model access:** (a) wait for the key; (b) a fake client that returns schema-valid placeholders.

## Decision

1(b), 2(b), 3(b), 4(c), 5(c), 6(b), 7(b), 8(b), implemented as `pipeline/runner.py` (command line `python -m pipeline.runner`), `pipeline/registry.py` (the input registry), `pipeline/fake_client.py` (the dry-run client), and the private workflow `.github/workflows/pipeline-step.yml` of owners-office-private.

- **Steps.** A step is one prompt part: `14Q` (question list, HQ), `15A` (pre-registration, company manager) and `18` (monthly letter, HQ) in this round. The prompt's front matter is the only list of a part's inputs; the registry maps each input name to an assembler. A declared input without an assembler, or a required input whose data cannot be found, fails the assembly with the full list of what is missing.
- **assemble** (local, `assemble 15A APP FY2026Q3 --run-date 2026-10-20`). Builds the inputs, checks them against the role's visibility with `llm.check_inputs()` before anything is written, and writes `runs/<TICKER|hq>/<run_date>-<part>/inputs/<name>.<md|yml|txt>` plus `manifest.yml` into the private repository: step, role, prompt id, part, version, revision and sha256 (also of 00 and 00D), variables, the placement context, pipeline fields, each input's sources (repository path and revision, workspace file, EDGAR accession and URL, run output) with sha256 and size, the digest of the thesis-ci schemas given to the model, the public commit (`pipeline_commit`) and whether it has uncommitted changes or is unpushed, the expected request hash (the `input_sha256` llm.py will log), a rough token estimate, and `created_at`. Uncommitted changes to `pipeline/`, `agents/`, `constitution/decision-rights.yml` or the requirements refuse the assembly unless `--allow-dirty` (recorded). Bundles are never overwritten.
- **Missing data.** A required input that legitimately has nothing yet becomes a YAML document with `status: empty` and a one-line reason, marked `empty` in the manifest; `calibration` says there are no settled predictions yet. Until `companies/<T>/dossier.md` exists, the owner's complete report text (`inputs/text/reports__<T>.txt` in the workspace) stands in for the dossier, and the manifest says so (`substitute: dossier`). An optional input may be left out only on purpose, with the reason in the manifest.
- **execute** (`execute <bundle> --backend {claude-code,api,fake}`). Verifies the bundle before anything else: input files and hashes (nothing unlisted), prompt hashes, the thesis-ci schema digests, and for real backends that the public checkout is the pinned commit without local changes (`--allow-unpinned` overrides, recorded). It then calls `llm.complete()` once and writes `outputs/`, `run.yml` (status, backend, attempt, model, usage, cost, request hash and whether it matches the manifest, versions, the planned §F2 destinations), `calls.jsonl` (the lines llm.py logged) and `reply.txt` next to the inputs. Refusals before the call write nothing; once the call is entered the outcome is always recorded, and `--retry` runs a failed bundle again, keeping the failed attempt under `attempts/<n>/`. A succeeded bundle is final.
  - **Backends.** `claude-code` is the default, as the owner decided; `api` is the Anthropic API; `fake` is the dry-run client. The choice is passed to `llm.complete()` as `backend=` as soon as its signature accepts it; until the follow-up adds that parameter, `api` and `fake` run on the current API path (the fake client stands in for the SDK client) and `claude-code` stops with `BackendUnavailable` (a `NotImplementedError`) before the bundle is touched.
  - **Where it runs.** Locally is the normal mode. Model calls refuse to run in the Actions of any repository other than owners-office-private, and the outputs always land in a checkout whose `repo.yml` says `visibility: private`.
  - **Printing.** Only counts, hashes, cost and error classes are printed; validation errors, refusal explanations and tracebacks go to `run.yml`. The `execute` and `pr-body` commands never print a traceback.
- **The call log (T7).** `runs/llm-log.jsonl` in the private repository is the persistent log, and the budget guard reads month spend from it: a local `execute` appends to it in the working tree (the operator commits it with the bundle), and the Actions route appends the run's lines to it on the default branch directly, so spend is recorded even when the review rejects the outputs. A run never edits the log on its review branch, so review branches do not conflict over it.
- **The Actions route (phase 2).** `pipeline-step.yml` in owners-office-private runs the same `execute` with `--backend api`, dispatched by hand with the bundle path until phase 2 wires triggers to it: it checks out the private repository at the dispatched branch and owners-office read-only at the pinned commit, installs the requirements, gives `ANTHROPIC_API_KEY` (its only secret) to the one step that runs `execute`, appends the call log on the default branch (three attempts if the branch moves), commits the run to a branch and opens a pull request (a draft when the step failed). Permissions are `contents: read` for the workflow and `contents: write` plus `pull-requests: write` for its one job; runs queue in one concurrency group.
- **place** (local, after review; `place <bundle> [--announced DATE] [--check]`). Only runs of a real backend are placed. It re-checks each output's hash, computes the destinations with `outputs.place()`, and for `prereg` sets `company`, `event`, `deadline`, `author` and `horizon` itself (the header recorded at assembly, or a fresh `edgar.prereg_header()` with `--announced` or `--window`), keeps the items untouched and validates the result against the schema. It refuses after the deadline and warns after the merge-by time. A destination that exists with other content is refused; the one exception is a pre-registration whose items are identical, which gets the new header before the deadline, and its stale `.ots` is deleted in the same change (0018). Public-bound output containing CJK characters is refused unless `--allow-cjk` (English-first policy, 2026-09-25; recorded). Public files are written on a branch (`pipeline/<scope>-<run_date>-<part>`, or the current non-main branch); private files go to their §F2 paths, which for most outputs are in the run directory itself. thesis-ci lint runs on both repositories before and after writing: any error the placement introduces restores every file written, and errors that were already there are reported as warnings (CI still requires them fixed before the merge). The result is recorded in `placement.yml` next to the run. Committing, pushing and opening pull requests stay with the operator; after the public merge, the timestamp workflow stamps the pre-registration.
- **dry-run** (`dry-run 15A APP FY2026Q3 --run-date 2026-10-20`). assemble plus `execute --backend fake` into `work/pipeline-dry-run/` in the workspace, outside both repositories, with a copy of the real call log so the budget guard sees real spend. The fake client answers each required output with a DRY-RUN placeholder that passes the thesis-ci schemas, and reports a rough token count so the cost accounting runs. `execute --backend fake` on a bundle inside the private repository is refused.
- **Isolation.** Visibility is checked at assembly and again inside llm.py. Stripped inputs are built with `pipeline/isolation.py`; `question_list_stripped` (from the placed 14Q list, with the seed recorded) and `thesis_without_loss_paths` are registered already for the steps that need them.
- **English-first.** The new public files are English; the Chinese names they must match (prompt variables, the todo label that marks a pre-registration candidate) are written as escape sequences. A test keeps them free of CJK characters.
- **Tests** (`tests/test_runner.py`, no network, no key): registry coverage for the three steps (also against the real prompts when the private repository is checked out next to this one), role visibility with the real `agents/*.yml`, isolation, manifest hashes and their checks, the fake execute and the budget guard, backends and environments, placement paths, prereg headers, CJK flags, rollback on lint errors, the workflow's permissions and secrets, and that nothing prints input or output text.

## Rationale

- **Local assembly.** The SEC User-Agent and the owner's report text are on the owner's machine; the bundle carries only documents and their addresses. Anyone can see in the bundle exactly what a model was given.
- **Pinning.** The same bundle always means the same request: the manifest records the request hash, and the run record says whether the call matched it. A prompt, schema or code change after assembly is refused instead of silently producing a different request.
- **Local execution by default.** It is what the owner decided (the subscription pays for the drafting calls), it keeps private inputs off any hosted log, and it works before an API key exists. Keeping the Actions route costs one workflow file and gives phase 2 an unattended path with the same bundle format.
- **One persistent log, written outside review branches.** Money spent is spent whether or not the outputs are accepted, so the budget guard must see it at once; writing it only on review branches would lose rejected runs and make parallel branches conflict.
- **Explicit empty documents.** A model told "no settled predictions yet" can say so; a model that silently lacks an input cannot tell a gap from a zero. Loud failures stay for inputs whose data should exist.
- **Deterministic header, branch-only public writes, lint before anything is public.** The model never decides a deadline, the public main never receives model output without a pull request, and CI rules are checked before the pull request exists.

## Rejected alternatives

- **Assembling inside the job that calls the model:** the SEC User-Agent and the owner's report would have to be copied into Actions, and the inputs would not be reviewable before the call.
- **Model calls only in the private repository's Actions** (the first design of this record): superseded by the owner's decision to run calls locally on the subscription; kept as the phase-2 API route.
- **Unpinned runs:** a bundle could run against prompts or code it was not assembled for, and the log could not say which.
- **llm.py's default `logs/`, or a log only per run:** the default is not versioned; per-run logs alone cannot answer "how much this month" without scanning every run, and lose rejected runs.
- **Omitting inputs that have no data:** the model cannot tell a missing input from an empty one, and the prompt's declared inputs would no longer be what it gets.
- **Model-written pre-registration headers:** a wrong date moves the deadline; 15A says the header is the pipeline's.
- **Writing public outputs to main:** the review and CI would come after publication.
- **Waiting for model access to test:** the whole path, including the budget guard and placement, can be exercised with a fake client today.
