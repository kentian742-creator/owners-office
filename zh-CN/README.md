# Owner's Office

**把一位投资者的判断公开记录下来，并接受检验。**

Owner's Office 是一位个人投资者的研究档案，全文称这位投资者为"主人"。这里跟踪的每家公司都有一份写成文字的论点，和 20 到 30 个可能证明论点错了的测试。每次财报发布之前，对业绩的预测连同概率先写下来并加上时间戳；发布之后，按事先定好的标准打分。错误公开记录。研究由一组 AI 角色在主人成文的投资宪法下起草和审计；主人只决定两件事：钱投向哪里，宪法要不要改。

**截至 2026-09-30 的状态：** 已建档七家公司，每份档案都已对照公司申报文件逐条核对过事实，发现的每个错误都记在[错误清单](mistakes.md)里。麦当劳是第一家由流水线直接从 SEC 申报文件建档的公司；接下来是 Alphabet、苹果和英伟达。第一批预测针对标普全球 2026 年第三季度的业绩，将在 2026-10-17 之前登记，所以目前还没有任何预测被打分。进展见 [docs/STATUS.md](../docs/STATUS.md)。

| 目前的记录 | |
| --- | --- |
| 已登记的预测 | 还没有合并的。标普全球的五条预测要在 2026-10-17 前登记，伯克希尔·哈撒韦的五条在 2026-10-25 前。 |
| 已打分的预测 | 还没有。第一批打分在标普全球发布财报之后，大约 2026-10-21。 |
| 对照申报文件核对的事实 | 根据主人自己的笔记整理的六家公司档案，2350 条事实里错了 116 条（4.9%）。流水线直接根据申报文件写出的第一份档案（麦当劳），769 条里错了 7 条（0.9%）。两次审计用的是同一个模型。 |

> **不构成投资建议。** 本仓库记录的是一位个人投资者的方法和预测记录。它不推荐任何证券，不公开任何估值或价格，也不执行任何交易。主人持有 AppLovin、标普全球（S&P Global）和伯克希尔·哈撒韦的股票，其余公司作为研究或参照跟踪；仓位大小从不公开。

## 为什么

投资者很少真正知道自己的判断有多好。论点写在笔记里，事后被改写；预测含糊到怎样的结果都说得通；一个好年份可以掩盖一套坏流程。Owner's Office 就是为了补上这些缺口：

| 常见的问题 | 本仓库的做法 |
| --- | --- |
| 论点永远不会错 | 每个论点都带测试：必须守住的数字、由另一个只看问题和申报文件的模型回答的是非题、论点每一部分必须重新审视的期限。每个门槛都在数据出来之前定好。 |
| 事后诸葛亮 | 预测在业绩公开之前提交，并用 [OpenTimestamps](https://opentimestamps.org) 加时间戳。某一期的业绩一旦公开，CI 就拒绝修改这一期的门槛。 |
| 没人核对的数字 | 每个事实都引用一手文件，例如 `[src:AXP-10K-FY2025#p45]`，没有出处的数字过不了 lint。每份档案和每次季度更新在合并之前，都要对照申报文件逐条做事实审计。 |
| 锚定 | 一个看不到论点的"盲读"模型回答同样的问题；它和起草模型意见不同的地方，就是复核最该花时间的地方。 |
| 自己给自己打分 | 已结算的预测按领域计算 Brier 分数和校准曲线，由记录而不是自我评估来说明主人的判断在哪些领域靠得住。 |
| 管理层说什么就信什么 | 管理层对股东的承诺记进"言行账本"，和主人自己的预测一样结算。 |

## 从这里看起

- **一家公司：** 先读 AppLovin 的[两分钟故事](companies/APP/story.md)，再看完整的[论点和测试](../companies/APP/thesis.yml)。其余档案：[标普全球](../companies/SPGI/)、[美国运通](../companies/AXP/)、[微软](../companies/MSFT/)、[伯克希尔·哈撒韦](../companies/BRK/)、[麦当劳](../companies/MCD/)、[拼多多](../companies/PDD/)。
- **规则：** [投资宪法](constitution/owner.md)：十四条规则和五条硬性底线，每一条都对应一项机器能执行的检查。
- **错误：** [错误清单](mistakes.md)，至今发现的每一个错误，以及因此改了什么。
- **来信：** [写给主人的月度信](letters/2026-09.md)。
- **进展：** [docs/STATUS.md](../docs/STATUS.md) 和[决策记录](../docs/decisions/)；整体设计见 [DESIGN.md](docs/DESIGN.md)。

## 怎么运转

1. **档案。** 每家公司有一份 `thesis.yml`（论点、评级和测试）、一篇两分钟故事、一张来源表和一本言行账本。估值只放在私有仓库，从不出现在这里。
2. **业绩之前。** 先冻结下一季度要回答的问题，再写下概率，在公司发布业绩之前合并并加时间戳。
3. **业绩之后。** 10-Q、10-K 或 8-K 一到，量化测试直接从申报文件计算；定性测试由独立模型判定，并且必须引用证据；季度更新逐条事实审计之后才合并。
4. **结算。** 预测按事先写好的标准打分，月度信如实报告哪里对了、哪里错了、系统因此改了什么。

十三个角色分工完成这些工作：每家公司一名分析员（"公司经理"）、行业研究员、协调者（"总部"）、抽取员和排版员，外加八个独立监督角色：事实审计、估值模型审查、红队、综合审查、设计审查、盲读、裁判和结算。它们都运行在 Anthropic 的 Claude Opus 5.5 上；每个角色能读什么、绝不能看什么，都设定在 [agents/](../agents/) 里。一个角色出了事实错误就会失去自主权，直到它的工作需要主人复核；记录干净了再赢回来。资金和修宪永远交给主人。

格式规范、lint 和打分工具单独发布为 [thesis-ci](https://github.com/kentian742-creator/thesis-ci)，任何按同样方式建立的档案都能使用。

## 适合谁看

- **写投资论点的投资者：** [thesis-ci](https://github.com/kentian742-creator/thesis-ci) 能像检查这个档案一样检查你自己的档案：测试在数据公布前写好，每个数字都有出处，业绩公布后门槛即被冻结。`pip install thesis-ci`，再运行 `thesis-ci init`。
- **为研究搭建大模型流水线的人：** [agents/](../agents/) 里的角色章程（每个角色能读什么、绝不能看什么）；[流水线代码](../pipeline/)（每次调用都记录输入的哈希，输出先校验再使用，过大的步骤拆成分片）；[决策记录](../docs/decisions/)可以当作设计日志来读，其中也记下了哪里出过错。
- **关注这些公司的读者：** 每份档案都写明论点、能证明它错了的测试，以及审计在其中发现的每一个错误。

另有一个私有仓库，存放不能公开的内容：估值、决策备忘录、含仓位大小的决策日志、完整研究报告和提示词。

## 不做什么

- 不给交易信号，不做回测，不预测股价。
- 不获取每日股价。价格只作为估值用的私有参考数据存在；公开文件唯一可以出现的价格，是公司自己披露的历史平均回购价。
- 不执行交易。资金永远由主人亲自决定、亲自操作。
