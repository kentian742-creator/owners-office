# 错误清单

公开记录系统和主人犯过的错。越公开越不愿认错，所以单独立一份清单：改主意算成绩，不算污点。年度“致自己的股东信”连同本清单一起发布。

## 收录什么

- **事实错误**：合并进档案的数字或引文错了（出处不对、读错、算错）。
- **判断错误**：事后按事先写下的标准结算，结论是错的，而且错在推理，不只是运气。
- **过程错误**：该做的检查没做、预注册晚了、测试门槛事后改了、上报漏了。
- **遗漏**：档案里没写、后来被证明要紧的风险或事实。

预测没有应验本身不算错误，它记在 `forecasts/` 里按 Brier 分数计分；只有过程或推理出了问题才进本清单。

## 格式

每条一个小节，最新的在最前。事实数字照常带 `[src:...]` 标签；不写金额、价格和仓位。

```markdown
### YYYY-MM-DD · 公司代码 · 类别

- 当时的判断：……（链接到 PR、预注册或更新记录）
- 实际情况：……
- 错在哪里：……
- 谁的错：公司经理 / 行业研究员 / 总部 / 审计 / 盲推 / 主人
- 改了什么：规则、测试、提示词或流程（链接到对应的提交或决策记录）
```

## 清单

### 2026-09-27 · MSFT · 事实错误

- 当时的判断：第 0 阶段的 MSFT 档案（`companies/MSFT/`）把所有者报告里的几处错误输入照搬到了每一个用到它们的地方。Microsoft 365 商业产品与云服务的收入包含本地部署的许可，却被当作其中的云部分，并与云业务的增速配在一起；自由现金流与非 GAAP 净利润之比的序列混用了两种定义，其中两年除的是 GAAP 净利润；OpenAI 的持股比例用的是后续几轮融资之前的数字，其会计处理也描述错了。较小的错误包括高管业绩股票奖励的考核指标、“没有发行股票”、分部的增速与利润率数字，以及亚马逊何时完成对 OpenAI 的出资。
- 实际情况：第一次事实审计对照 10-K、10-Q、8-K、委托书和公司自己发布的电话会议记录核对了 460 条事实：379 条准确，41 条判为错误，5 条口径问题，4 条无法确认，14 条只有二手来源，17 条只有报告支持。错误成簇出现：Microsoft 365 这一行及建立在它上面的增速差（9 条），现金转换率序列（9 条），OpenAI 持股及其会计处理（6 条），业绩股票奖励（5 条），股票发行（2 条），另有九条单项事实。第 41 条已撤回：审计和总部的第一份裁定依据微软 2025 年 10 月的公告，判断 OpenAI 向微软支付收入分成的截止日期；公司经理在修订中发现，2026 年 4 月的修订协议已经取代了那些条款。按修订后的协议，报告是对的。
- 错在哪里：和其他档案一样，这份档案是在取不到申报文件时依据报告建立的，并且在事实审计之前就合并了；错误来自所有者的报告，被照搬进档案，每一个错误输入都扩散到了所有用到它的地方。被撤回的那一条暴露了审计和裁定中的另一个漏洞：一条以协议为依据的事实，没有先查协议此后是否修订过就被下了判断。
- 谁的错：系统第 0 阶段的建档过程；第 0 阶段的档案不计入任何角色的信任等级（`docs/decisions/0016`）。源头是所有者的报告，它与一手文件的差异已登记在私有勘误表。被撤回的那条结论是审计和总部的；它在任何文件据此改动之前就被发现了，手工运行的审计同样不计分。
- 改了什么：档案已于 2026-09-27 按一手文件改正，每个反复出现的错误在它出现的所有地方都改了，新登记了 32 个公开来源；报告原文不改，没有任何测试的门槛、方向或规则改变。总部为审计和裁定记下了这条教训：一条事实以协议为依据时，先查协议后来有没有修订，再判定它错。

### 2026-09-27 · AXP · 事实错误

- 当时的判断：第 0 阶段的 AXP 档案（`companies/AXP/`）照搬了所有者报告里的一些数字和说法，没有对照申报文件核实：1989 年以来盈利大幅回撤的次数、存款每年的利息成本、返还给股东的净利润比例（被说成公司披露过的数字）、经营分部的个数、公司在 2015–2016 年间何时重设盈利目标、每多一美元卡费带来的会员权益成本、2025 年 1 月与司法部和解的条款，以及针对 AI 代理代为购物的购买保障是否已经推出。
- 实际情况：第一次事实审计对照 10-K、10-Q、8-K、委托书和司法部的公告核对了 338 条事实：295 条准确，17 条错误，5 条口径问题，4 条只有二手来源，17 条只有报告支持。17 条错误实为八个问题，大多在几处重复出现：回撤次数（4 条；是五次，不是四次），存款利息成本（4 条），返还净利润的比例（2 条），和解（2 条），每美元卡费的会员权益成本（2 条），以及分部个数、目标重设和代理购买保障（公告的是未来的承诺，并未推出）（各 1 条）。五条口径问题中有四条涉及联名卡在消费额中的占比：公司先后用过两种定义，而有一个测试的系数正建立在这种混用之上。
- 错在哪里：和 APP、PDD 一样，档案是在取不到申报文件时依据报告建立的，并且在事实审计之前就合并了。错误来自所有者的报告，未经核实就照搬进了档案。
- 谁的错：系统第 0 阶段的建档过程；第 0 阶段的档案不计入任何角色的信任等级（`docs/decisions/0016`）。源头是所有者的报告，它与一手文件的差异已登记在私有勘误表。
- 改了什么：档案已于 2026-09-27 按一手文件改正，改为引用一手文件而不是报告，新登记了 40 个公开来源；报告原文不改。系数混用两种定义的测试 AXP-Q8 自 FY2026Q4 起由 AXP-Q17 取代，新系数只用一种定义；AXP-Q8 作为记录保留，没有任何生效中测试的门槛被改动。

### 2026-09-25 · PDD · 事实错误

- 当时写了什么：第 0 阶段的 PDD 档案（`companies/PDD/`）照搬了所有者报告里的几处说法，没有对照申报文件核实：PDD 何时停止披露 GMV 和用户数、近十年亏损的年数、新增股本的来源、2022 年商品销售的先例，以及没有注明口径地采用罚款前业绩公告里的 FY2025 数字。
- 实际情况：第一次事实审计对照申报文件核对了 372 条事实：304 条准确，12 条错误，4 条口径问题，20 条只有二手来源。已按 20-F 和 6-K 改正；FY2025 以经审计的数字为准，业绩公告口径并列写出。
- 错在哪里：和 APP 一样，档案是在取不到 SEC 数据时依据报告建立的，并且在事实审计之前就合并了。
- 谁的错：系统第 0 阶段的建档过程（不计入任何角色的信任等级，决策 0016）；源头是所有者的报告，差异已登记在私有勘误表。
- 改了什么：每份档案在被预注册依赖之前都先过事实审计（接下来是 AXP、MSFT、SPGI、BRK）。

### 2026-09-25 · 流程 · 私有信息写进了公开文件

- 当时写了什么：公开的进度文件 `docs/STATUS.md` 按公司写出了两家公司在所有者选定的尺子下价格分档怎样变化。价格分档只应放在私有仓库（硬规则 H4）。
- 实际情况：这一行从公开仓库的第一次提交（2026-09-25）起就在，同一天被新的英文用语检查发现；已改写为只说两家公司各变动一档，细节在私有仓库。
- 错在哪里：公开内容检查不扫描 `docs/`，这一行是汇总迁移结果时手写的。
- 谁的错：系统（第 0 阶段的工程搭建），不属于任何角色。
- 改了什么：公开内容检查同时扫描 `docs/STATUS.md`；STATUS 对私有变化只写数量。

### 2026-09-25 · APP · 事实错误

- 当时的判断：第 0 阶段建立的 APP 档案（`companies/APP/thesis.yml`）写债务本金与净债务时照抄了企业报告里的约数；写股本变化时把期初取成了下一年的年末；管理层标准 (a) 的五年读数混用了重述前后两套数字。
- 实际情况：第一次事实审计按 10-K、10-Q 逐条核对了 237 条事实，七条判为错误，实为两处问题（债务本金与净债务；股本期初），另有一处口径问题。报告里的债务约数来自电话会上的口头说法，与申报文件不符。
- 错在哪里：建档时 SEC 的 EDGAR 还不可达，数字取自报告，没有逐条回到一手文件；档案在合并之前也没有先过事实审计。
- 谁的错：系统的建档过程（第 0 阶段的工程搭建，不属于任何角色，按 `docs/decisions/0016` 不计入信任等级）；源头是所有者报告里的约数。
- 改了什么：档案按一手文件改正（提交 d471ebb）；报告原文不改，差异登记进私有仓库的勘误表；其余五家公司的档案在第一次预注册之前补跑同样的事实审计，以后每份档案在合并之前都先过事实审计。
